# Colosseum Battle Environments 1.7.1-fidelity.1

This test build addresses the two largest issues visible in the 1.7.0-fidelity.1 recording: trainer actions still reading like interpolated procedural motion, and source moves completing without all of their visible Waza effect layers.

## Trainer source animation

- Trainer extraction advances from the three-gesture/two-reaction approximation to a **five-frame native B1 gesture timeline plus five-frame native B1 reaction timeline**.
- Every retained frame is generated by evaluating the original HSD animation clip from the user's GC6E01 source.
- Runtime blends **only neighboring frames from the same source clip**. It no longer draws a long straight morph between distant poses, which was responsible for much of the shoulder/arm "swimming" appearance.
- Gesture-family selection now prioritizes the actor's lead-hand motion and penalizes broad opposite-arm movement, making the selected source clip much more likely to be an actual battle gesture/throw rather than a generic two-arm performance.
- The Poké Ball hand anchor uses the same dense source-frame blend as the visible trainer.
- Extractor revision is bumped to **13** and trainer cache format to **26**, forcing old 1.7.0 trainer caches to rebuild while preserving reusable arenas/audio.

## MoveFX / Ember

- MoveFX cache revision advances to **15**.
- Curated moves now honor all explicitly audited source WZX phases. For Ember (move 52), that means:
  - `wzx_hinoko_attack.fsys`
  - `wzx_hinoko_damage.fsys`
  - `wzx_hinoko_sp1.fsys`
- 1.7.0 selected only the first attack-like bank and the damage bank; the `sp1` bank containing the visible Ember presentation could therefore be omitted even though damage resolved normally.
- WazaSequence timing identifiers are now namespaced per source phase so `attack` and `sp1` entries with the same local identifier cannot overwrite each other.
- GPT1 entry matching is phase-strict so a particle row from `sp1` cannot accidentally start a same-numbered generator from `attack`.

## Scope

This is still a fidelity iteration rather than a claim that every trainer semantic action or every Waza entry type is fully decoded. The important change is that visible trainer deformation is now sourced from a much denser chronological slice of the real B1 animation, and audited multi-layer moves no longer discard their auxiliary visual bank.
